I’m building a transcript review/editing app. The current transcript area feels too much like a technical transcription UI, with hover buttons appearing over individual words. I want to redesign this part first.

Priority: make the transcript area feel like a clean, editable document.

The transcript should feel closer to Google Docs, Notion, or a polished article editor, not like a dense transcript debugging panel. Users should be able to read, edit, and navigate the transcript naturally.

Core UX goals:
- The transcript should look like a document/editor.
- Text should be easy to read and edit inline.
- Avoid intrusive hover controls above words.
- Keep controls subtle, contextual, and out of the way.
- Double-clicking any word should seek the video/audio to that word’s timestamp.
- Clicking a timestamp should seek the video/audio to that segment.
- The currently playing sentence/paragraph should be highlighted gently.
- Follow-along mode should scroll the document naturally while playback runs.
- Editing should feel smooth, with no weird popovers blocking the text.

Redesign the transcript center panel with this structure:

1. Document header
- Editable transcript title
- Small metadata row: duration, language, speakers, source file
- Optional status: Saved / Saving / Unsaved changes

2. Document toolbar
Place this above the transcript, not floating over text:
- Search transcript
- Find/replace
- Undo / redo
- Speaker display toggle
- Timestamp display toggle
- Follow along toggle
- Export button or export menu
- More options

3. Transcript document body
Each transcript section should appear like a clean document block:

Example:
[00:07] Speaker 1
Okay, we’ve got a founder right here. What’s your company?

[00:14] Speaker 2
We make software for the cannabis industry.

[00:18] Speaker 1
What level of software?

Design notes:
- Timestamps should sit quietly in the left gutter or inline before each speaker block.
- Speaker names should be editable.
- Transcript text should be directly editable.
- Use comfortable line height and paragraph spacing.
- Avoid heavy borders around every line.
- Avoid per-word buttons.
- Use subtle active-state highlighting for the current spoken sentence.
- Search matches should be highlighted clearly but not aggressively.
- Current search result should be visually distinct from other matches.

Important interactions:
- Single click in text: place cursor for editing.
- Double click word: seek media to that word timestamp.
- Click timestamp: seek to segment start.
- Click speaker name: edit/rename speaker.
- Select text: show a small floating toolbar near the selection, but only after text selection. Toolbar actions: Copy, Highlight, Bookmark, Add note.
- Right-click selected text: show contextual menu with Copy, Highlight, Bookmark, Add note, Export selection.
- Keyboard shortcut Space should play/pause unless the user is actively typing.
- Cmd/Ctrl+F should focus transcript search.
- Cmd/Ctrl+Z and Cmd/Ctrl+Shift+Z should undo/redo edits.
- Esc should close menus or clear selection.

Do not show buttons when hovering over individual words. Word-level interactions should feel invisible and intuitive.

Media sync behavior:
- The transcript should be synced to the video/audio at word level.
- During playback, highlight the current sentence or paragraph.
- The active line should stay visible when follow-along is enabled.
- When the user scrolls manually, temporarily pause auto-scroll until they re-enable follow-along or click “return to current position.”
- Add a small “Return to current playback position” button when the user scrolls away from the active section.

Editing behavior:
- Inline editing should preserve timestamps behind the scenes.
- Edits should autosave.
- Show a subtle “Saving…” / “Saved” indicator.
- Support undo/redo.
- Support splitting paragraphs with Enter.
- Support merging paragraphs with Backspace at the beginning of a block.
- Support speaker rename globally.
- Make it possible to mark a paragraph or section as reviewed.

Visual direction:
- Clean, calm, document-first interface.
- The transcript body should have a centered max width, like a document page.
- Use a soft page background or card, but avoid making it feel boxed-in.
- Typography should be highly readable.
- Controls should be minimal and only appear when needed.
- The UI should prioritize reading, editing, and playback navigation.

Main outcome:
Redesign the transcript panel so it feels like a polished document editor with media-synced transcript functionality. The user should be able to read, edit, search, and navigate the transcript without fighting intrusive controls.
